# 指令、元素分析与应用快照

## 调用链

```text
Requirement Step
→ InstructionRegistry
→ Instruction.execute(ExecutionContext, inputs)
→ BrowserActions / 其他受控服务
→ Instruction.verify(result)
→ Step.verify(result)
→ Step 检查点
```

指令注册表只保证稳定 ID、输入、输出、异常和成功校验；它不拥有运行目录、检查点或重试状态。Step 才是业务恢复边界。

## InstructionSpec

一条指令必须声明：

- `instruction_id`、语义版本、名称和平台；
- 输入、输出和依赖元素 ID；
- 前置条件、成功条件和副作用等级；
- `execute()` 和独立的 `verify()`。

注册表拒绝重复 ID、缺失或多余输入、缺失或多余输出、非 Mapping 结果和验证失败。未知底层异常转换成稳定错误，原始异常只保留为本地 cause，不把敏感消息写进公开错误文本。

## 逐步浏览器分析

Codex 在获得真实浏览器授权后，按一个需求步骤一个需求步骤工作：

1. **建立页面身份**：记录 URL 模式、标题、当前标签页、iframe 层级和登录状态信号；
2. **只观察当前目标**：从需求动作确定目标角色，例如输入框、按钮、下拉框或下载入口；
3. **生成候选定位**：稳定 ID/属性优先，其次标签、可访问名称和稳定文本；必要时使用锚点限定上下文；
4. **拒绝脆弱信号**：动态 class、绝对层级、序号和坐标不能直接成为已验证定位；
5. **校验定位**：匹配必须符合预期数量，并验证可见、可用/可点击和页面身份；
6. **刷新复核**：对计划晋升的元素至少重新加载或重新进入页面后复核；
7. **执行一个原子动作**：只在元素校验通过后执行当前指令；
8. **观察结果**：通过 URL、标题、目标元素、筛选状态、下载文件或其他明确成功条件复核；
9. **记录证据**：保存脱敏 DOM 摘要、截图、动作结果和运行 ID；
10. **进入下一步**：失败时停在当前步骤，生成 `UnresolvedElement` 或 `UnresolvedInstruction`，不猜测后续页面。

验证码、滑块和短信只检测、截图并转人工。任何页面提交或外部写入仍受 Preview/Live 授权约束。

## 元素策略

影刀公开文档中的稳定思想可映射为（核验页面见[官方资料索引](sources.md#影刀-rpa)）：

| 影刀概念 | 本仓库实现 |
| --- | --- |
| 元素捕获与编辑 | 候选 TOML + 浏览器验证证据 |
| 默认属性 / XPath | 排序后的定位候选，稳定属性优先 |
| 元素锚点 | 元素依赖与作用域定位 |
| AI 辅助定位 | 语义/视觉兜底，不能替代唯一性验证 |
| 校验与修复 | 候选验证批次 + 显式 diff |
| 云元素自动更新 | 不采用；使用应用快照和显式升级 |

## 快照生命周期

顶层 `elements/` 和 `instructions/` 是源库。生成器通过 `snapshot_catalog()`：

1. 扫描并验证顶层元数据；
2. 解析 `element:<id>` / `instruction:<id>` 依赖闭包；
3. 拒绝重复 ID、未知依赖、循环、路径逃逸、符号链接和硬链接；
4. 复制到 `src/<package>/elements/` 和 `src/<package>/instructions/`；
5. 写入包含来源、目标、依赖、复制时间和内容哈希的 `catalog.lock.json`，复制时间不参与内容一致性判断；
6. 在每次 `check` / `run` 前重算应用副本哈希。

运行时只验证应用副本。顶层源库之后发生变化，不影响现有应用。

## 候选门禁

V2 Requirement 使用 `UI-*` 的 `UnresolvedInstruction`。候选指令必须记录应用内实现、Fake 测试和锁条目；真实验证通过后还必须记录真实测试证据。候选状态允许 `doctor` 和无副作用测试，但阻止正常 `run`、审核和推送。
