# ADR-026：元素与指令使用应用快照

- 状态：**已被取代**
- 日期：2026-09-01

> **取代说明**：被 [ADR-028](ADR-028-v2-structural-simplification.md) 取代（2026-09-03）。跨应用资产复用从未发生：第二个应用换平台后可复用资产为 0，快照与依赖闭包机制搬运不了任何东西。

## 背景

公共元素和平台指令需要跨应用复用，但运行中的应用不能因顶层库更新而静默改变行为。候选元素和指令还需要在真实验证前保留完整流程，同时阻止误运行和推送。

## 决策

- 顶层 `elements/` 和 `instructions/` 只保存真实验证过的源资产；
- 生成应用时复制实际使用项及依赖闭包；
- 应用使用 `catalog.lock.json` 固定类型、ID、版本、来源、目标、哈希、依赖和复制时间；复制时间不参与内容一致性判断；
- 应用运行时只读取包内副本，不读取或同步顶层库；
- 候选能力保留在应用内并进入同一锁文件，状态为 `candidate`；
- 已有应用升级必须先展示来源版本、哈希和文件 diff；
- `rpa-core` 继续使用 uv 本地路径依赖，不纳入快照。

## 结果

优点是运行可复现、升级可审核、公共库故障不会扩散到已验证应用。代价是公共修复不会自动下发，需要显式升级和回归测试。这个代价是有意选择的安全边界。

## 被否决方案

- 运行时直接引用顶层库：更新会无审查地影响所有应用；
- 云端自动同步：不满足离线可审计和显式升级要求；
- 把指令做成 JSON/YAML 解释 DSL：降低 Python 可测试性，并增加第二套运行时；
- 复制 `rpa-core`：会造成公共框架分叉和安全修复漂移。
