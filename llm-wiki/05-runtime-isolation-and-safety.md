# 运行隔离与安全授权

## 第一批运行目录隔离

阶段 2 的文件运行时使用应用本地、Git 忽略的 `runs/<run_id>/`。每次 `run` 或 `resume` 必须在创建目录前通过需求、清单、架构与敏感信息门禁，并满足：

- `run_id` 是 1 至 128 字符的安全单目录组件；
- 运行目录精确等于当前应用的 `runs/<run_id>`，不能由调用方声明任意外部根目录；
- checkpoint、event logger 和所有声明运行路径/身份的服务与同一 `ExecutionContext` 精确绑定；
- checkpoint/event 拒绝最终路径的符号链接和硬链接，Preview 拒绝 `runs`、运行目录及预览目录符号链接；
- 同一 `run_id` 从读取 checkpoint 到 cleanup、最终保存全程持有跨进程排他锁；
- 不同步骤使用独立 Preview 文件名，同一步重试才允许原子替换自己的预览。

当前排他锁使用 POSIX `flock`，不支持时 fail-closed。Windows 运行机必须先实现并验证等价的进程退出自动释放锁。更强的 dirfd/openat 级父目录 TOCTOU 防护属于后续本机威胁模型加固。

## 多店铺浏览器隔离

每个账号或店铺必须对应：

```text
一个独立 Chrome 进程
+ 一个持久化 Profile
+ 一个动态租用的调试端口
+ 一把 Profile 排他锁
+ 一个独立运行目录
+ 一套独立检查点
```

不得让不同店铺共享 Profile、Cookie、端口租约或检查点。

## BrowserManager 责任

`BrowserManager` 负责：

- 解析浏览器程序路径；
- 获取和续租调试端口；
- 获取 Profile 排他锁；
- 启动或连接浏览器；
- 创建账号对应的浏览器会话；
- 按生命周期策略保留或结束进程；
- 释放端口与锁；
- 清理前确认进程和租约状态。

业务应用不能决定浏览器进程何时退出。

## 生命周期策略

- `KEEP_OPEN`：本地开发和人工验证默认使用，方便处理验证码并检查页面。
- `REUSE_UNTIL_IDLE`：统一运行机器可复用浏览器，空闲后由运行时回收。
- `TERMINATE_ON_FINISH`：只有明确配置时使用。

生命周期策略不改变 Profile 排他要求。

## 授权层次

```text
离线测试
  ↓ 无外部访问
真实浏览器授权
  ↓ 允许指定应用、账号、步骤的读取/查询/下载
Preview
  ↓ 所有业务写入转为本地预览
Live 单次授权
  ↓ 只允许指定运行、目标、步骤和数据范围
回读验证
```

`--mode preview` 只是写入策略，不等于已经获得真实浏览器操作授权。打开浏览器、登录、点击、查询和下载仍需要开发人员明确授权。

## Preview

Preview 可以在已授权的真实流程中读取、筛选、查询和下载，但必须拦截：

- 页面提交；
- 飞书写入；
- 数据库写入；
- 正式 Excel 覆盖；
- NAS 或其他正式目标写入；
- 真实告警发送。

预览写入当前运行的 `write-previews/`，并校验字段、类型、唯一键、范围、数量和目标位置。

## Live

Live 授权至少包含：

- `app_id`；
- `run_id`；
- 账号或店铺别名；
- 允许写入的步骤；
- 写入目标；
- 数据范围和预计记录数；
- 有效期和仅本次有效标识。

适配器在真正产生副作用前再次验证授权。CLI 检查通过不能代替适配器门禁。

## 人机验证

遇到验证码、滑块、短信或其他风控：

1. 停止当前自动动作；
2. 记录 `HumanVerificationRequired`；
3. 保存脱敏截图和页面上下文；
4. 保持浏览器供人工处理，除非生命周期策略另有明确要求；
5. 不模拟绕过、不调用第三方打码服务；
6. 人工处理后按恢复策略重新验证状态。
